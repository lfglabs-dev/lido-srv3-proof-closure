## Reproduction

Run `make prove`, `make test`, and
`lake build LidoSRv3 LidoSRv3Audit LidoSRv3Test AccountAddressChecks`
from this checkout with the pinned dependencies, Python 3.10+ and Bash 4+.
On macOS, put supported Python and Bash installations ahead of the system
versions on PATH. The local test run used `LEAN_NUM_THREADS=2` and
`RAYON_NUM_THREADS=2` to limit concurrent Lean processes. `make test` includes the
transitive trust check, source differential tests, metadata checks, immutable
fixture checks and regression builds. Per-guarantee build commands appear on
the website and in the registry.

## Compiler checks

`AllocCapacity.oneModule_compiles_to_official_ir`,
`ConsolidationFee.function_spec_compiles`, and
`DepositRollback.checked_prefix_compiles` establish compiler acceptance of
their unchanged specifications. Their proofs compose input validation,
function-body compilation and constructor compilation. Input validation uses
fully transparent reflexivity; all resulting proof terms are checked by the
Lean kernel. These declarations depend only on `propext`, `Classical.choice`
and `Quot.sound`. No new native proof exception is used.

The signing-key memory regressions use proved array/list equivalences to
check the original overlap, framing and wraparound assertions without costly
byte-array reduction. The trust audit discovers production theorems from all
compiled modules, loading standalone command-line drivers separately and
checking that repeated declarations retain the same types and dependencies.

Compiler acceptance does not establish correspondence with deployed bytecode.
The exact Lean statements and each card's assumptions define the delivered
scope.

## Trust scope

The dependency audit checks 1,259 explicit disclosures and 16,645 compiled
claims, including unprinted supporting results. Every checked claim uses only
`propext`, `Classical.choice` and `Quot.sound`; no native proof exception is used.
Two auxiliary mapping-base separation lemmas take explicit non-collision
premises. Slot-derivation identities do not prove Keccak injectivity.

## Proof boundaries

- Supported-module counter and type invariants are assumed through
  `A-SUPPORTED-MODULES`; they are not proved for every deployed module.
- External-body storage preservation relies on `A-NO-REENTRY`.
- Live address renaming is conditional for `claimWithdrawalsTo`; a concrete
  state-renaming instance and the full bodies of `transferFrom`,
  `requestWithdrawals` and `unwrap` remain outside the proved scope.
- General deployed-bytecode correspondence, SHA-256 implementation correctness
  and authentic beacon history remain explicit assumptions or open boundaries.

Independent review of this delivery revision is separate from executable
validation and has not been completed. The report does not claim independent
audit acceptance.
