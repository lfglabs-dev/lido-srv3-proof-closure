# Proof Evidence

This directory contains the executable proof target register for the Verity/Lean
SRv3 economic model.

- `LOCKFILE.md` pins the Lido PR #1811 and Verity references.
- `reserve-separation.md` covers SRV3-P1.
- `deposit-conservation.md` covers SRV3-P2.
- `module-balance-conservation.md` covers SRV3-P3.
- `report-before-reward-consistency.md` covers SRV3-P4.
- `reward-correctness.md` covers SRV3-P5.
- `status-gating.md` covers SRV3-P6.
- `exited-count-correctness.md` covers SRV3-P7.
- `topup-conservation.md` covers SRV3-P8.
- `allocation-capacity.md` covers SRV3-P9.
- `reward-minted-reporting.md` covers SRV3-P10.
- `fee-update-consistency.md` covers SRV3-P11.
- `module-param-update-consistency.md` covers SRV3-P12.
- `module-status-update.md` covers SRV3-P13.
- `module-addition-consistency.md` covers SRV3-P14.
- `module-share-update-consistency.md` covers SRV3-P15.
- `logs/proof-report.json` is generated by `make prove` after Lean checks
  `LidoSRv3.lean`. Its `build.verified_source_tree` is a Git tree ID for the
  exact checked inputs: `LidoSRv3/`, `LidoSRv3.lean`, `lakefile.lean`,
  `lake-manifest.json`, and `lean-toolchain`. All five must be clean before the
  build. The reported Lean version is derived from the executable used for the
  build, recorded in `logs/prove.txt`, and required to match `lean-toolchain`.
  Generated logs and report artifacts are intentionally excluded, so this
  identifier is deterministic and non-self-referential.

Run:

```sh
make prove
```
