## Source-to-consumer conclusions

1. **Real request and consumed reply.** `SszRootCall.call` invokes `lowLevelStaticCall` directly. Target is exactly `0x000F3df6D732807Ef1319fB7B8bB8522d0Beac02`; value is zero; caller is the actual parameter. Payload is precisely the 32-byte big-endian encoding of a zero-extended uint64 timestamp, without a selector, matching `abi.encode(childBlockTimestamp)`. `afterCall` binds this invocation's outcome to decode and feeds its decoded root through index construction, validator hashing and proof verification. `source_entry_projection` is a structural theorem, not an alternate runtime oracle or extra call.
2. **Ordering and rejection.** Slot SHA precedes checked proof-length subtraction and sibling comparison. Any slot failure produces no root attempt. The root call precedes index construction, leaf construction and proof verification. Failed calls and empty successful data become RootNotFound; 1–31 bytes fail ABI decoding; 32 or more bytes decode the first word and allow trailing data. These checks match the pinned source sequence. Typed error constructors distinguish these paths; universal exact ABI revert-byte encoding is not claimed by the new theorem.
3. **Physical call behavior and no-code case.** The reused primitive reads code size from the supplied physical World. No code yields success with empty bytes without consulting the external interpreter; decode rejects it. Thus whole-run success derives code presence instead of assuming it. Forbidden state change and rejected replies remain failed attempts. The primitive's documented general precompile treatment is not enlarged here: this literal EIP-4788 address is not a precompile. External execution is still interpreted by `StaticCall.External`.
4. **Index, fields and hash input.** Existing consumed source functions use the actual slot, fork configuration, offset, credentials and witness. Neighbor arithmetic checks overflow/range before concatenation and packed-index width checks. Fixed state-root index is 11 at depth 3, as pinned Solidity. Pubkey length must be 48 and its SHA input is those bytes followed by 16 zero bytes. Numeric fields are uint64 little-endian cells, slashed is the correct bool cell, credentials come from the verifier argument, and the eight-cell/seven-pair validator tree uses the source order. The new entry does not strengthen these functions' established semantic interpretation.
5. **Independent branch composition.** The proof loop rejects empty input, checks the shifted parent before each hash, orders sibling/leaf by index parity, checks final index 1 before root equality, and consumes the exact returned root. `afterRoot_success` derives the independent `SszProofFold.Branch`, not a restatement of a success boolean. `run_success` (lines 166–193) connects that branch to `firstWord (fromBytes data)` where `data` is the actual successful external reply. The public theorem exposes these connections directly.
6. **Trace and world scope.** Success derives exactly one accepted root STATICCALL attempt with the actual request and bytes. Slot rejection yields zero such attempts; failed root calls are retained. This trace intentionally observes the root call, not a complete transcript of typed SHA operations or nested external execution. `run_world` establishes unchanged World on every outcome of these read-only typed semantics. It does not purport to derive full compiled CL transaction rollback from an unrelated state counter.
