# Gateway witness loop and derived router arithmetic

At core `17005714f151e5502c559932319a3f2f74ac2436`, the typed gateway loop executes the actual SSZ verifier entry for each row before evaluating that row's pending balance. It copies the same witness public key, converts the resulting headroom to wei and updates the unchecked accumulator in input order. The canonical batch theorem derives the proofs from one semantic registry and one header, with a single common expected withdrawal credential. No successful-verifier Boolean, supplied limit array or final digest is an input to that theorem.

This is a bounded source-model increment. `checkLengths` represents the five actual length reads and cardinality guard at lines 163–175. `loop` starts after the intervening temporal checks and credential lookup/type check. Role/pause checks precede the prefix. The two functions deliberately remain separate; their conjunction is not a theorem about full-entry failure order. Aligned typed rows represent the loop's corresponding array reads, not a proof of raw calldata decoding or arbitrary memory safety.

## Executed order and independent specification

Each row checks public-key length 48, strict increasing index (the first index 0 is allowed), activation, and `SszVerifierEntry.sourceEntry`; only then does it call the accepted checked limit evaluator. `headroom` independently uses natural-number remaining balance with exit/slash and minimum rules. The proof relates this specification to the executed evaluator, including a zero result when already at/above target even if minimum is zero. Exited/slashed validators still pass SSZ first and skip the later potentially overflowing addition.

`SLOTS_PER_EPOCH` is an actual uint256 input with a runtime zero-divisor error, matching the constructor's lack of a nonzero check. Quotient ≤ slot derives that the uint64 epoch cast is exact; the successful domain assumes only a nonzero divisor and the actual activation inequality. Pending values remain unrestricted uint256 words. For nonexited, nonslashed rows, the honest success domain requires effectiveBalance+pending < 2^256. SSZ verification does not imply that caller-supplied pending bound.

The canonical consumer uses `SszStatePlacement.canonical_validator_entry`: Electra/Fulu schemas, semantic validator values, opaque other-field roots, capacity 2^40 and actual selected list membership. Every selected member must have the same expected credential and satisfy source ordering/activation. The configured GI instance is the accepted150 previous/current instance with an explicit pivot, not a claimed deployed fork. Standard typed SHA and the exact trusted EIP-4788 oracle response remain explicit. No hash injectivity, cryptographic authenticity, consensus provenance or full EVM behavior is proved.

The source limit/count uint64 widths derive exact wei conversion, roundtrip and total sum < 2^256. `loop_spec` also relates arbitrary successful loop executions to their computed keys, limits and accumulator. `router_checked_from_loop` constructs the router input from that actual output and derives the arithmetic obligations of PR275 from its real guards on arbitrary module-returned allocation words. It derives exact allocation sum, uint256 fit and the alignment/uint64-gwei conditions of `AmountsAdmitted`; nonzero minimum amounts remain the later helper's genuine success condition. This bridge is arithmetic only. It does not execute the router withdrawal or beacon program, or prove any module returns successfully. The canonical theorem supplies the loop-success observation when composing these two results.

`TopupGatewayConfigWords` reads the physical Live.World contract words at the source namespace. The count is low 64, target bits 160–223, and minimum the following word's low 64. Its packed-word theorem separates those values from intervening and unused fields. This interprets the declared source layout; it is not a compiler refinement, setter-reachability or deployed-layout theorem. The root-owned Solidity fixture separately checks actual getters and compiler layout.

## Validation and limits

The final targeted Lean build passed 1,285 jobs: 16 source theorems, 40 regression examples and 11 axiom queries, with no warnings in the new files. The arithmetic observation/bridge and byte/word conversion queries use propext and Quot.sound; some semantic/canonical loop proofs additionally use Classical.choice. No sorry, admitted theorem, native decision axiom or external checker is used. The final log reports the test module as Built (11s). The two source targets were already successful and remained up to date in the cache; the final command reused their artifacts and checked their dependency identities through the test imports. It does not report rebuilding either source target. The full exact log is retained; the increased recursion/heartbeat limits in tests only permit kernel evaluation of the finite 50-sibling fixtures.

The Lean regressions exercise competing failures, sourceEntry execution, zero divisor and epoch edges, overflow and exit/slash short-circuit, paired keys/pending, strict sort and wei units. Hash fixtures are explicitly synthetic: constant-zero SHA simplifies control-flow tests, while a byte-sum fixture tests a changed common credential. They do not establish cryptographic separation of arbitrary proofs. Real SHA/proof mutations are additionally checked by the independent Solidity harness described in `solidity/README.md`.

The root-owned Solidity fixture inherits the unmodified actual TopUpGateway and CLValidatorVerifier, constructs an independent two-member sparse registry/header and invokes public topUp. Only the root response and external router recorder are mocked; it does not use the repository's no-op verifier harness. Its seven tests include three 1,024-run fuzz properties and actual layout checks. This finite execution evidence includes role/time/WC fixture setup, not a theorem that those stages are reachable or universally succeed.

Total limits are distinct from actual allocations; the recorder can return with no allocation while positive limits trigger the source timing update. No no-reentry or frame premise closes these gaps.
