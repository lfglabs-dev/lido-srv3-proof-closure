# ACCOUNT: actual accounting getter consumed by mint authorization

This additive consumer starts from main 340 `53871e66833bd45190eb83dffc15439ceafa9c42`. It replaces the independent `steth.locatorAccounting` context used by positive-fee mint authorization with the result of the executed physical-target `Lido._accounting()` CALL, specialized to the actual pinned `LidoLocator.accounting()` immutable getter. It preserves the complete physical-pause 340 and treasury-call 324 conclusions on an explicitly derived entry. Old source/public domains and all provider, AllGuarantees, Trust and dependency configuration files are unchanged.

Core source is `lidofinance/core@17005714f151e5502c559932319a3f2f74ac2436`. See [SOURCE-MAP.md](SOURCE-MAP.md) for complete relevant source/assembly paths, exact caller-versus-callee compiler behavior, and deployment scope.

## Executed order and public result

`ReportFeeAccountingCall.execute` runs the existing physical router report writes, getter and checked fee calculation in that order. A failed report/getter/arithmetic stage returns the original World and makes no accounting call. Zero fee skips the accounting call and mint/distribution/treasury. It retains the original authorization metadata while applying the existing physical pause interpretation; successful zero-fee World equality with the unprojected entry is not asserted.

For positive fee, the call receives the actually committed post-report router World, with the physical pause interpretation. Its target is the low 160 field of StETH's physical `LOCATOR_AND_MAX_EXTERNAL_RATIO_POSITION`, not the treasury environment's immutable locator. Its caller is Lido's self address, value is zero, and its payload is exactly `96 24 e8 3e`. The compiler's target-code check precedes the CALL. The actual source getter body emits its ABI word; the legacy caller decodes that raw word. `finish` consumes the returned World with only its authorization metadata replaced by the decoded address, then invokes actual mint, actual module transfers, actual treasury STATICCALL on their intermediate World and actual treasury transfer. It does not rerun the report after CALL.

The public theorem is `LidoSRv3.Audit.Guarantees.PAccount1.actual_report_accounting_call`. Its sole execution premise is the whole new runner's successful outcome. `Success` retains:

- The actual report/getter/checked-fee equations producing the consumed fee.
- The zero-fee/no-accounting-attempt case, or the positive actual accounting CALL, its physical target, source getter/raw response/decoder equations, returned-World preservation, exact immutable origin and actual authorization equality.
- The exact old 340 executor equation on the explicitly derived entry, the entire old 324 `OldEffect` and the entire physical-pause `PhysicalEffect`. No ledger, report, mint, payment, event, treasury-read or intermediate physical invariant conclusion is dropped.

The positive derived entry is exactly `withAccounting before resolved`; the zero-fee entry is exactly `before`. The existing pause projection is still obligatory. `actual_report_accounting_call_failure_restores` restores the entire original entry World, including both legacy metadata fields, physical words, abstract shares and router, even after later treasury failure. Diagnostic accounting and treasury attempts remain separate ordered lists; the new attempt is marked CALL (`isStatic=false`).

No caller-supplied authorization equality, successful stage, positive-fee restriction, fit, frame or nonalias premise is added. Actual mint success derives caller equality with the decoded result. The literal pause/total slot invariant and actual payment/treasury composition are reused, not replaced with a weakened certificate.

## Source specialization and retained boundaries

`AccountingCall.Environment.code` is an effective deployed-code table indexed by the actual physical target. `none` means no code; `some Getter` means the identified pinned immutable getter implementation with its constructor immutable. It supplies neither a raw reply nor a purported frame theorem. `getter` executes the nonpayable selector branch and produces the ABI return itself; World preservation is derived from this body and consumed by the composition.

This is explicitly a source-specialized CALL interpreter. A generic mutable callee cannot be silently treated as readonly: solc 0.4.24 really emits CALL and could permit reentrancy/world changes. The fixture demonstrates this with a writable raw callee outside the specialized proof. The old arbitrary-context domains remain untouched. Other deployed code or arbitrary mutable callbacks are not additional cases of this new source-specialized consumer.

The pinned deployment scripts place LidoLocator behind OssifiableProxy. Matching a physical target to its deployed proxy/current implementation and immutable configuration remains the existing deployment/external-implementation boundary. The Lean code does not claim to execute proxy dispatch, implementation-slot loading, constructor validation, delegatecall trace or upgrades. The fresh Solidity fixture does execute the complete real proxy and getter, and verifies that changing the real implementation changes the address consumed by authorization. `Getter`'s typed immutable is a code/configuration input; it is not a proof of successful deployment or constructor nonzero validation.

Abstract shares mapping, deployed component identities/separation, full Accounting report prefix and reward/rebase suffix, model Nat-address admission, complete ABI/memory provenance, gas/resource exhaustion and universal instruction/bytecode refinement retain their earlier boundaries. The new caller fragment explicitly accounts for its return-size and address-cleanup guards; no extra allocation panic or signed-size rejection is invented or hidden. The pure pause/context projections are semantic metadata interpretations, not additional early EVM SLOAD traces.
