\section{Appendix A: Reader glossary}
\label{app:glossary}

\begin{description}
  \item[Router] The SRv3 component that allocates deposit work across staking
  modules and records aggregate module accounting.
  \item[Module] A staking-provider lane managed by the router.
  \item[Accepted report] Oracle balance data that has passed the modeled SRv3
  validation checks and may update accounting state.
  \item[Withdrawal reserve] ETH kept aside for withdrawals, not available for
  new deposits.
  \item[CL] Consensus layer, the Ethereum system that records validator
  activity.
  \item[Lean] A proof checker that can verify theorem statements. This package
  does not ship Lean theorem artifacts.
  \item[Verity] The modeling reference pinned for this work. This repository
  ships a local Verity-style executable economic model.
  \item[P0] Highest-priority property class. Here it means an accounting claim
  important enough that the executable package should either check it or clearly
  say why it remains open.
  \item[Proof target] A precise executable check tied to source anchors,
  assumptions, model files, and proof logs.
  \item[Assumption] A named premise that the executable target may use but does
  not prove.
  \item[Trust boundary] The edge of the proof: what the model proves, what it
  assumes, and what remains for separate review.
\end{description}
